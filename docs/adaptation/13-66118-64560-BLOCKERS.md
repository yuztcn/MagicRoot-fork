# 64560 6.6.118 适配阻塞记录

当前 MagicRoot 64560 链使用：

```text
assets/t64560_v36
assets/cred_target
assets/t64560_cred
assets/kaslr_slide_* (6.12)
```

这些二进制为 6.12.58 链接期编译，内含 6.12 偏移/调用点；6.6.118 的
`k_itimer`/cred/begin_new_exec 等常量不同，直接运行会写错地址并可能 panic。

## 已可复用

- 6.6.118 目标符号表：`binary-sources/66118/syms_66118.txt`
- BTF 几何/调用点：`binary-sources/66118/profile-66118.json`
- 6.6 UAF 前提静态验证：见 `work/adapt-66118/boot/REPORT.md`
- rootkit issue #6 P0：每发 v36 后 `pkill -9`、不按发杀 cred_target、
  目标地址校验、panic 用原生日志 + /proc/uptime 判定；已进入 6.12 run.sh。

## 缺失

- 6.6.118 的 t64560_v36 / cred_target / t64560_cred 二进制或其完整可编译源码；
- 对应 KASLR slide anchor（6.6 缺 `ufshcd_issue_dev_cmd`，需换锚点）；
- 6.6 版 64560 KSU LKM/模板。

ColorOS 17 KMRoot APK 的 6.6.118 plant/su 目标 build 为
`...-g9bc34d5b0c79-abogki537459655-4k`，与本机
`...-gf17133276a57-abogki518694926-4k` 不同，不可直接运行。

## 结论

98260 链可用 Windows 测试链验证；64560 6.6.118 需要先补齐上述二进制/源码，
当前只完成静态可行性分析和 P0 规则，不应在 6.6.118 上直接执行 64560。
