## KSU 侧

### g928

HOneClick 的 6.18 资产：

```text
ksu-template.ko   430,243   e33b7c5dbbef2206571c99b13eadf1bc99a11d3182f6e5f3e2540c6ca9568003
ksud            4,990,848   4f7d5fd65631915ea579ff406bd9cbe58217f2c91dac6527f5b2f28ad4508171
manager.apk    13,637,206   b4a059ace71de2fa65cc7f12b1c58d55fc23ab25e057ee4230ce779742abe450
syms           6,344,533    转成 name 0xaddr 后使用
```

策略：

```text
98260-61821 -> flavor 强制 kernelsu
             -> ksud_kernelsu
             -> ksu-template.ko + syms_61821_kernelsu.txt
             -> 缺 manager 时 pm install 内置 v3.3.1
```

### ge186

**不补 ko patch。** 原因：

1. 没有 ge186 boot image/kallsyms，无法生成 6.18 ge186 的 syms；
2. HOneClick 的 `ksu-template.ko` vermagic 是 g928，不是 ge186；
3. 仅改 vermagic 而沿用 g928 符号地址会错位，可能直接 panic；
4. BRM 的可用路径是 BakaSU `ksud late-load --kmi android17-6.18`，
   但仓库/本机没有 BakaSU ksud + manager 资产，无法离线补齐。

因此 `98260-61821-brm` 的 `KSU_ENABLE` 被强制为 0，只保留 rootd。
如果后续提供：

```text
ge186 boot image / kallsyms
或 BakaSU ksud + manager
```

才可以再评估 ge186 的 KSU 路径。
