# 6.1.128 g8a496 / g2e1f Adaptation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add two independently derived, exactly selected 6.1.128 profiles to the existing proven static 98260 and CGA handoff without changing other kernel chains.

**Architecture:** Extend the locked g264 static-payload manifest with boot/disassembly-proven constants. Add a deterministic, standard-library ELF rewriter that maps the g264 CGA base's 225 absolute symbols and 220 live stubs by name, then register the resulting per-build assets in the existing runner and Compose deployment flow.

**Tech Stack:** Python 3 standard library, AArch64 ELF, Android mksh/Bash, Java/Compose controller, Gradle release build, `zipalign`/`apksigner`.

**Spec:** `docs/superpowers/specs/2026-11-04-61128-old-kernels-design.md`

## Global Constraints

- Only add `6.1.128-android14-11-g8a4968670f1c` and `6.1.128-android14-11-g2e1f0741dafb`; exact `uname -r` selection, no model/BTF/ROM/config hash gate.
- Preserve g264 base payload SHA-256 `cc0b9693dcdba564585c39dfe3eb386860f1cede4251d0d7aca63d1e51762843` and CGA base SHA-256 `6381ad16a904af8d7d2a702e04994ed22c3fd01c6e00229ec584634034a56c09`.
- Both targets use `task_cred=0x838`, `real_cred=0x830`, `k_itimer=0x108`; do not apply the `0x840/0x118` module patch family.
- Do not alter g7d M6, g19a, 43499/Pad3, M6 Shell 1.9/B2, other kernel assets, `main/app/src/`, package/version, or single-page UI.
- No boot images, APKs, keys, device logs or user data in git/source zip. No UAF/rootd/LKM/reboot execution during implementation.
- Keep scripts LF and native assets binary-safe. Every commit ends with `Co-Authored-By: Kimi <noreply@moonshot.cn>`.
- “Static adaptation” is the completion claim; no end-to-end device validation is implied.

## Review Focus

- **Same data symbols, different code anchors:** expect distinct payloads; Task 1 checks both timer/cred constants and output diversity.
- **Missing symbol or unknown stub:** expect generation to fail instead of emitting a partial LKM; Task 2 adds negative tests.
- **Unexplained binary changes:** expect only mapped symbol values, mapped stub qwords and `.modinfo` vermagic to differ; Task 2 audits every changed byte.
- **Cross-kernel deployment:** expect each release to receive only its own payload/CGA; Task 3 checks exact filters and blocked legacy/M6 handoffs.
- **Old-profile regression:** expect all nine previous manifest payloads and existing CGA bases to retain their bytes; Tasks 1, 3 and 4 run reproducibility/hash checks.
