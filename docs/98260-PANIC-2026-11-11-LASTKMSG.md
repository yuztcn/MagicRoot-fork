三次都发生在 exploit 父进程 `wait4` 触发的 victim 收尸路径。前两次出错地址不是
内核指针，而是 trace 文本；结合 `trace_tail_open()` 在回收窗口内 malloc/fread
trace 的实现，可以确认扫描器自己的堆页抢到了刚释放的 slab 半页，并在命中后让
`timerqueue_del/rb_*` 把文本当作 rb_node。

修复落点：

1. `find_page_alloc()` 与 victim ledger 只接受覆盖完整 8 KiB 的 order>=1 自身分配；
2. 扫描缓冲在启动时预分配并预触页，回收窗口内不再产生匿名页缺页；
3. `exec_ready` 保证回收布防完成后才允许 exec/killer；`exec_entered` 区分真正的
   post-exec 正常退出与 setup 失败；
4. payload 日志 O_SYNC 镜像，App 在下一次部署前导出 `98260.log` 和 `.log.sync`。

参考：HOneClick 2.0 Beta 6 commit `8acea35e7753d75137b45e57e7bf9c7b793b47a8`。
静态门禁与真机状态分别记录于 `进度.md`；117 适配仍无对应真机。
