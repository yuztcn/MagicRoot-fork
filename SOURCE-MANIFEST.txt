Runtime symbol completion (2026-11-11)
--------------------------------------
Report: docs/RUNTIME-SYM-COMPLETION.md

Official KernelSU 32727 changed its embedded LKM to reference 11 new symbols.
ko_patch now prints MISSING_SYM and accepts an optional /proc/kallsyms dump for
exact-name completion; runtime addresses are used as-is and zero/hidden values
are refused.  tools/test_runtime_syms.py covers the resolver, zero-address
refusal and the shell retry/fail-closed contract.

A real device run proved the runtime path cannot bootstrap itself in real-cred:
kptr_restrict=2 hides addresses from uid 2000, and rootd only starts after
finit_module, which waits for the ready file the retry is trying to produce.
The primary fix is static: tools/sync_manager_symbols.py appends the 11 symbols
to 14 kernelsu tables only when every overlapping symbol matches a donor table
(219/226 names).  The carved 6.12.76, 6.6.127 and 6.18.32 manager variants all
report 236/236 resolved (16/16 profiles); ten profiles were additionally
verified against exact kernel dumps with zero mismatches.  The runner's rootd
wait now defaults to 6 seconds and is only a fallback when rootd already exists.
Four profiles (61258b, aph112, 6123, 6138y) have no local exact image and are
covered by donor-overlap evidence only.

Static tests cover five flavors, 6.6/6.18, Fina's wrapper, idempotency and late-load
RC.  Fake and primary save the real late-load RC before writing logs and require zero
for primary success as well.  Exact boot images supplied missing init_cred values for
g856, 61258c, 6689, f171, g554, ga812 and g264.  A supplemental exact 6658 boot
(SHA-256 bf22d44ba14dd87327ea7b5dc8bb28fd71b1ae4b71c39e1f10a204c62039e278)
exported 109221 kallsyms and proved init_cred=0xffffffc082170748.  All five 6658
Flavor tables had zero mismatches across every overlapping symbol before the single
entry was added.  The previously listed unavailable profiles are now covered; unknown
future profiles remain fail-closed.  No new device-side UAF was executed.
